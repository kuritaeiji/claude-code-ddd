## レビュー指示

上記の6つのドキュメントをレビューし、以下の観点で問題点と改善提案を報告してください。

### 1. CLAUDE.md 定義への準拠チェック（最優先）

CLAUDE.md に定義された各ドキュメントの記載要件を満たしているか確認してください。

| ドキュメント               | 必須記載項目                                                                                                                            |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| production-requirements.md | プロダクトの目的・背景 / 対象ユーザー / 解決する課題 / スコープ（やること・やらないこと）/ 開発フェーズ                                 |
| domain.md                  | ドメインモデル図（全集約俯瞰・多重度含む）/ 集約ごとのセクション（エンティティ・値オブジェクトの定義・ビジネスルール・ドメインイベントと副作用） |
| usecase.md                 | ユースケース一覧（コマンド）と対応APIエンドポイント / クエリ一覧（CQRS Read側）と対応APIエンドポイント                                  |
| architecture.md            | 技術スタック / アーキテクチャ構成図と層の責務 / 層をまたぐデータ構造のパターン / 非機能要件（バリデーション・エラーハンドリングの方針） |
| schema.md                  | ER図 / テーブル定義（カラム名・型・制約）/ ドメインモデルとのマッピング                                                                 |
| repository-structure.md    | ディレクトリ構成とその意図                                                                                                              |

また、**本来そのドキュメントに書くべきでない内容が混入していないか**もチェックしてください。
（例: usecase.md にリクエスト・レスポンスの型詳細が書かれていないか）

### 2. ドキュメント間の整合性

以下を横断的にチェックしてください。

- **プロダクト要求定義書 ↔ ユースケース定義書**: ユースケース一覧は一致しているか？production-requirements.mdにあってusecase.mdにない（または逆）のものはないか？
- **ユースケース ↔ ドメインモデル**: ユースケースに登場するエンティティ・値オブジェクトはdomain.mdに定義されているか？
- **ユースケース ↔ 技術仕様書**: APIエンドポイントとユースケースは対応しているか？
- **技術仕様書 ↔ リポジトリ構造**: アーキテクチャの層構成とディレクトリ構成は一致しているか？
- **ドメインモデル ↔ DBスキーマ**: domain.md のエンティティ・値オブジェクトが schema.md のテーブル・カラムに正しくマッピングされているか？（schema.md が存在する場合）

### 3. 各ドキュメントの完全性

- 必要な情報が欠けていないか？
- 曖昧な記述や未定義の用語はないか？

### 4. DDD設計の妥当性

- 集約境界は適切か？
- ドメインイベントの定義は十分か？副作用は網羅されているか？
- 値オブジェクトとエンティティの分類は正しいか？
- ドメイン層とアプリケーション層の責務分担は正しいか？

### 5. アーキテクチャの妥当性

- オニオンアーキテクチャの依存方向は守られているか？
- CQRSの適用範囲は適切か？
- 非機能要件（バリデーション・エラーハンドリング）の設計は十分か？
