# プロダクト要求仕様書（PRD）

## タスク管理バックエンドAPI

---

## 1. プロダクト概要

### 1.1 目的

タスク管理バックエンドAPIを通じて、DDDの以下の概念を実践的に学習する。

- エンティティ・値オブジェクト
- リポジトリ・ドメインサービス
- ドメインイベント・CQRS
- オニオンアーキテクチャ

### 1.2 対象ユーザー

DDD・オニオンアーキテクチャを実践的に学びたいGoバックエンドエンジニア（本プロジェクトの開発者本人）。

### 1.3 解決する課題

| 課題                     | 説明                                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 概念と実装の乖離         | DDDの書籍で学んだ概念（集約・値オブジェクト・ドメインイベントなど）を実際のGoコードに落とし込む経験が不足している |
| アーキテクチャ設計の迷い | オニオンアーキテクチャにおける層の責務分担や依存方向を、動くコードを通じて体感的に理解したい                      |
| CQRS適用の判断軸         | Read/Write分離の具体的な実装パターンと、その適用メリットを実務レベルで習得したい                                  |

---

## 2. スコープ

### やること

- ユーザー管理（登録・非活性化）
- タスク管理（作成・更新・削除）
- タスク一覧・詳細取得（CQRS Read側）
- ドメインイベントによる集約間の副作用処理（UserDeactivated → 担当者除外）
- エラーメッセージの多言語化（英語・日本語）
- ドメイン層・インフラ層のユニットテスト

### やらないこと

- 認証・認可（実装しない）
- ページネーション高度化（オフセットベースのみ）
- 外部イベントバス連携（インメモリ実装のみ）
- フロントエンド・UIの実装
- 本番環境へのデプロイ・インフラ構築

---

## 3. 開発フェーズ

| フェーズ | 内容                                                                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Phase 1  | ドメイン層の実装（エンティティ・値オブジェクト・リポジトリIF・ドメインイベント）                                                                      |
| Phase 2  | ドメイン層の単体テスト（エンティティ・値オブジェクトのビジネスルール検証）                                                                            |
| Phase 3  | インフラ層の実装（gorm リポジトリ・インメモリイベントバス）                                                                                           |
| Phase 4  | インフラ層の単体テスト（リポジトリの CRUD・イベントバスの配信）                                                                                       |
| Phase 5  | ユースケース層の実装（コマンド・クエリ）                                                                                                              |
| Phase 6  | コントローラー層の実装（net/http ハンドラー）                                                                                                         |
| Phase 7  | 統合確認（`go run` でサーバー起動 → curl で全エンドポイントの動作確認・ドメインイベント副作用確認）・`/review` によるコードレビュー・リファクタリング |
